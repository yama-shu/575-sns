## 背景・目的

[S-12 通報](../design/basic/04-screens.md#1-画面一覧)（[FR-05-01](../requirements/01-requirements.md#fr-05-健全性)）を実装する。

**健全性の機能が片肺になっている。** ブロック（[FR-05-02](../requirements/01-requirements.md#fr-05-健全性)）は
[#60](https://github.com/yama-shu/575-sns/issues/60) で画面から使えるようになったが、**通報だけ画面が無い**。
api を直接叩くしかない。

api は [#36](https://github.com/yama-shu/575-sns/issues/36) で実装済みである（`POST /api/v1/posts/:id/report`）。
**この Issue は web だけで閉じる。**

## やること

- [ ] 通報のモーダルを作る
- [ ] 投稿カードから開けるようにする（[下記](#どこから開くか)）
- [ ] 通報理由の文言を決める（[下記](#理由の文言を決める)）
- [ ] 応答ごとの文言を用意する（[下記](#断られ方が3種類ある)）
- [ ] README を更新する

## 完了条件

### 通報できる

- [ ] 理由を選んで通報できる
- [ ] 理由は4つから選ぶ（スパム / 嫌がらせ / 不適切 / その他）
- [ ] 補足を書ける（任意・500文字まで）
- [ ] 送ると**受け付けたことが分かる**
- [ ] `Esc` で閉じられる
- [ ] 開いたときに最初の項目へフォーカスが移る

### 出す場所

- [ ] 投稿詳細（S-03）から開ける
- [ ] ユーザーページ（S-04）の投稿から開ける
- [ ] **自分の投稿には出ない**（BR-07）
- [ ] 未ログインでは出ない

### 断られたとき（[下記](#断られ方が3種類ある)）

- [ ] すでに通報済み（409）のとき、その旨が分かる
- [ ] 自分の投稿（422）のとき、その旨が分かる
- [ ] 見えない投稿（404）のとき、理由を区別しない文言が出る

### 共通

- [ ] **JavaScript が無効でも通報できる**
- [ ] `npm run lint` `npm run typecheck` `npm run build` が通る

## やらないこと

- 運営向けの通報一覧（S-13。別 Issue。権限の設計が要る）
- 利用者そのものの通報（api は**投稿の通報**しか持たない）
- 通報の取り消し（api に無い。届いた通報を消せると運営の判断材料が減る）
- 通報後の非表示化（[FR-05-03](../requirements/01-requirements.md#fr-05-健全性) は運営の操作。S-13 で扱う）

## 実装上の注意

### どこから開くか

[基本設計 04 §2](../design/basic/04-screens.md#2-画面遷移図) の遷移図は `S-03 → S-12` と `S-04 → S-12` を描いている。

**投稿カードの footer に置く。** カードは S-01 / S-02 / S-03 / S-04 のすべてで使われるため、
図が求める2経路を満たし、さらに全体・フォロー中からも通報できる。

図より広くなるが、**通報できる場所を絞る理由が無い**。
目にした場所で通報できないと、わざわざ詳細を開き直すことになる。

- 自分の投稿には出さない（BR-07。api も 422 で断る）
- 未ログインでは出さない（api が 401 で断る）

### 理由の文言を決める

api の `reason` は `spam` / `harassment` / `inappropriate` / `other` である。
**日本語の文言は設計に無い。** ここで決める。

| 値 | 画面の文言 |
| --- | --- |
| `spam` | スパム・宣伝 |
| `harassment` | 嫌がらせ・攻撃 |
| `inappropriate` | 不適切な内容 |
| `other` | その他 |

**`other` を既定にしない。** 既定のまま送られると運営の判断材料にならない。
選ばせる。

### 断られ方が3種類ある

api は状況で違う応答を返す。**同じ文言にしない。**

| 応答 | 意味 | 画面 |
| --- | --- | --- |
| 409 `ALREADY_REPORTED` | すでに通報済み | 届いていることを伝える |
| 422 `CANNOT_REPORT_SELF` | 自分の投稿（BR-07） | 削除できることを伝える |
| 404 `NOT_FOUND` | 見えない投稿 | **理由を区別しない**（BR-10） |

409 を黙って成功にしない。[#36](https://github.com/yama-shu/575-sns/issues/36) が
「黙って成功を返すと『通報が届いた』と誤解する」として冪等にしなかった判断を、
画面でも守る。

### 送ったあとに何を出すか

**モーダルを閉じて終わりにしない。** 送信できたことが分からない。

受け付けた旨をモーダルの中に出し、閉じるのは利用者に任せる。
通報は結果がすぐ見える操作ではないため、**送れたこと自体を伝える必要がある**。

### JavaScript が無いとき

[#52](https://github.com/yama-shu/575-sns/issues/52) の「詠む」と同じ形にする。
モーダルを開くボタンをリンクにし、`/posts/:id/report` のページを用意する。
