## 背景・目的

[S-10 プロフィール編集](../design/basic/04-screens.md#1-画面一覧)（[FR-01-03](../requirements/01-requirements.md#fr-01-アカウント)）を実装する。

**登録したあと、表示名も自己紹介も変えられない。** [#60](https://github.com/yama-shu/575-sns/issues/60) でユーザーページができ、
自己紹介を出す場所はできたが、入れる手段が無い。

api も無い。[基本設計 05 §ユーザー](../design/basic/05-api.md) は `PATCH /api/v1/me/profile` を定めているが未実装である。

**api と画面を1つの Issue で扱う。** 追加する経路は1本で、
[#58](https://github.com/yama-shu/575-sns/issues/58) のように分けるほどの分量ではない。

## アイコンは対象外にする

[FR-01-03](../requirements/01-requirements.md#fr-01-アカウント) は「表示名・自己紹介・**アイコン**を設定できる」としている。
**このうちアイコンは扱わない。**

画像を置く場所が設計されていない。オブジェクトストレージの選定も、
[ADR-0007](../adr/0007-hosting-conoha-vps.md) が決めた単一 VPS でどう持つかも決まっていない。
`users.avatar_url` という列はあるが、**URL を利用者に直接入力させる形にはしない**。
任意の外部 URL を画面に埋め込むことになり、閲覧者の情報が第三者へ渡る。

判断には ADR が要る。**この Issue では表示名と自己紹介だけを扱い、
FR-01-03 を部分的にしか満たさないことを明示する。**

## 実装上の注意

### 空にできることを確かめる

自己紹介は**消せなければならない**。一度書いたら消せない項目は、
書くこと自体をためらわせる。

`PATCH` で「その項目に触れていない」と「空にする」を区別する。
省略されたら変えない、空文字が来たら消す。

**`omitempty` を使わない。** Go の `omitempty` は空文字を「無い」ものとして
送らないため、この2つを区別できなくなる。ポインタで受ける。

### 更新後の値を返す

保存できたかを画面が確かめられるようにする。**送った値をそのまま画面に残さない。**
サーバーが正規化した結果（前後の空白を落とすなど）と食い違う。

### ナビゲーションに自分の場所を足す

[基本設計 04 §2](../design/basic/04-screens.md#2-画面遷移図) が
「すべての画面からグローバルナビゲーション経由で S-01 / S-02 / S-04（自分）/ S-10 へ
遷移できる」としている。いまは S-01 / S-02 しかない。

[#50](https://github.com/yama-shu/575-sns/issues/50) で項目を配列にしてあるため、追加は行を足すだけで済む。

### 失敗したときに入力を消さない

[#52](https://github.com/yama-shu/575-sns/issues/52) と同じ形にする。`useActionState` の状態に本文を持たせ、
JavaScript が無い環境でも再描画後に残るようにする。
