## 背景・目的

形態素の列を、上五・中七・下五の3つに区切る。

区切りは**形態素の境界にしか置けない**。単語の途中で切ってはならない。
複数の区切り方が可能な場合、最も自然なものを選ぶ必要がある。

```
✅ 古池や / 蛙飛び込む / 水の音
❌ 古池や蛙 / 飛び込む水 / の音       ← 「水の音」を分断している
```

判定エンジンの中で最も判断が要る部分。

## 実装上の注意

### 最適化に凝らない

総モーラ数が18以下に限られるため、形態素の数は最大18。
素朴な二重ループ（最大324回）で十分に速い。

[NFR-01-01](../requirements/01-requirements.md#nfr-01-性能) の150ms の予算において
**支配的なのは形態素解析であり、この探索ではない**。
ここを最適化しても全体の速度はほとんど変わらない。

### スコアの重み 100 の意味

```
スコア = ズレ数 × 100 + 区切りコスト(i) + 区切りコスト(j)
```

区切りコストの合計は最大でも20程度にしかならない。
したがってズレ数が1つでも少ない候補が必ず勝つ。

これは「定型に区切れるなら、多少不自然でも定型を選ぶ」という意図的な設計である。
ユーザーにとって「定型」判定の価値が高いため。

TC-SS-04 がこの挙動を固定する。

### C単位を先に試す理由

A単位は分割が細かく候補が見つかりやすいが、複合語の途中で切れやすい。

```
「選挙管理委員会」
  C単位: 選挙管理委員会           （切れない）
  A単位: 選挙 / 管理 / 委員 / 会  （どこでも切れる）
```

C単位で成立するならそれが最も自然。成立しない場合に限って細かい粒度を許す。
