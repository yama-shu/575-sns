## 実装上の注意

### 経路を足す

[#60](https://github.com/yama-shu/575-sns/issues/60) で `/@:handle` を `next.config.ts` の rewrite で
`/users/[handle]` に割り当てた。**その下の階層は届いていない**
（`/@tarou/extra` が 404 になることを確認済み）。

`/@:handle/following` と `/@:handle/followers` の rewrite を足す。

### 一覧に操作を置かない

api は各項目に `following` を返すが、**この Issue ではボタンを置かない**。

[#60](https://github.com/yama-shu/575-sns/issues/60) でフォローの操作は `redirect` でページごと描き直す形にした。
一覧の中で押すと一覧全体が描き直され、**どこを押したのか分からなくなる**。

一覧は「誰がいるか」を見て、ユーザーページへ移動するための画面にする。
操作はユーザーページで行う。

### 部品を使い回す

一覧の並びと「もっと読む」は [#50](https://github.com/yama-shu/575-sns/issues/50) の `Timeline` と同じ作りにする。
**ただし別の部品にする。** `Timeline` は投稿カードを前提にしており、
`Post` と `RelationUser` を1つの部品で扱うと分岐が増える。

「もっと読む」がリンクでもある形（JavaScript 無しでも遡れる）は踏襲する。

### 0件のときに何を出すか

[#50](https://github.com/yama-shu/575-sns/issues/50) と同じく、次の行動が分かる文言を出す。

| 画面 | 状況 | 出す内容 |
| --- | --- | --- |
| S-05 | 誰もフォローしていない | 全体タイムラインへ誘導する |
| S-06 | フォロワーがいない | 詠むことを促す（自分のとき） |
| S-11 | ブロックしていない | その旨だけを伝える |

### 一覧に出ない相手がいる

[#68](https://github.com/yama-shu/575-sns/issues/68) のとおり、閲覧者をブロックしている相手と
利用停止・退会した相手は api が一覧から除く。

**画面はその差を説明しない。** ユーザーページのフォロワー数と一覧の件数が
食い違って見えることがあるが、理由を書くと誰が除かれたかを教えることになる（BR-10）。
