## 背景・目的

CI が PR に投稿するカバレッジのコメントが、**比較できない2つの値を並べている。**

```
| api | 60.8% | 90% | ⚠️ |
```

**60.8% は api モジュール全体**の値である。一方 **90% は [詳細設計 04](../design/detail/04-test-design.md#カバレッジ目標) が
usecase 層に対して定めた目標**であり、モジュール全体の目標はどこにも定めていない。

**テストが不足しているのではなく、集計が目標と対応していない。**

## 実測値

`go test ./... -covermode=atomic -coverprofile` の出力を層ごとに集計した。
結合テストを含む（`API_TEST_DATABASE_URL` を与えて実行）。

| 層 | 実測 | 目標 | |
| --- | ---: | ---: | --- |
| `internal/usecase` | **97.2%** | 90% | 達成 |
| `internal/infra/postgres` | **79.6%** | 70% | 達成 |
| モジュール全体 | 60.8% | （定めていない） | — |

**設計書が目標を定めている層は、いずれも達成している。**

### 全体が低い理由

テストを書いていないパッケージが**分母の 23.6%（368 文）**を占める。
`go test ./...` は各パッケージを**そのパッケージ自身のテストでのみ**測るため、
これらは 0% として計上される。

| パッケージ | 文数 | 実測 |
| --- | ---: | ---: |
| `internal/handler` | 365 | 53.2% |
| `internal/usecase` | 360 | 97.2% |
| `internal/infra/postgres` | 285 | 79.6% |
| `internal/domain` | 107 | **0.0%** |
| `internal/prosody` | 98 | 94.9% |
| `cmd/api` | 94 | **0.0%** |
| `internal/circuitbreaker` | 71 | 100.0% |
| `internal/db` | 47 | **0.0%** |
| `cmd/migrate` | 46 | **0.0%** |
| `internal/config` | 43 | **0.0%** |
| `cmd/cleanup` | 18 | **0.0%** |
| `internal/password` | 13 | **0.0%** |
| `internal/job` | 8 | 100.0% |
| `internal/requestid` | 5 | 100.0% |

0% の7パッケージを除くと全体は 79.5% になる。

**`internal/domain` の 0% は実態と異なる。** 値オブジェクトの検証は usecase と
handler のテストから実行されているが、`-coverpkg` を指定していないため計上されない。

## 指標の表記が誤っている

コメントは「**C1（分岐網羅）**」と書いているが、**Go の `cover` は分岐網羅を測らない。**
測っているのは文網羅である。

prosody は `--cov-branch` を指定しており、こちらは分岐網羅で正しい。

## 実装上の注意

### `-coverpkg` は入れない

`-coverpkg=./...` を指定すると、あるパッケージのテストが他のパッケージを
通った分も計上され、`internal/domain` の 0% は解消する。

**採らない。** 数値の意味が「そのパッケージのテストが到達した範囲」から
「どこかのテストが通った範囲」に変わり、**層ごとの目標と対応しなくなる。**
必要であれば別途判断する。

### 集計は awk のまま行う

このスクリプトはリポジトリルートから実行され、そこに `go.mod` が無いため
`go tool cover` は使えない（既存のコメントに記載のとおり）。
プロファイルの形式は「位置 文の数 実行回数」であり、層の切り分けは位置で行える。
