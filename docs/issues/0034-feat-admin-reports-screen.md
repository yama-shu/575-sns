## 背景・目的

[S-13 通報一覧（運営）](../design/basic/04-screens.md#1-画面一覧)（[FR-05-03](../requirements/01-requirements.md#fr-05-健全性)）を実装する。

api は [#74](https://github.com/yama-shu/575-sns/issues/74) で実装済みで、通報の確認も非表示化も `curl` では行える。
**画面が無いため、運営が実際には使えない。**

これが M4 の最後の画面である。基本設計 04 の 13 画面が揃う。

> **api も1箇所足す。** `/me` が `is_admin` を返さないため、
> **web は自分が運営かどうかを知る手段が無い**（[下記](#ナビゲーションに出すために-is_admin-が要る)）。

## 実装上の注意

### ナビゲーションに出すために `is_admin` が要る

`/me` は `handle` / `display_name` / `bio` / `avatar_url` しか返さない。
**web は自分が運営かどうかを判断できない。**

出し分けずに全員へ出すと、運営向けの経路があることを教える。
[#74](https://github.com/yama-shu/575-sns/issues/74) が 403 ではなく 404 を返すようにした判断と噛み合わない。

`/me` の応答に `is_admin` を足す。**本人の情報しか返さない**ため、
[基本設計 05](../design/basic/05-api.md) の `User` は本人向けの応答にしか使われておらず
（登録・ログイン・本人取得の3つ）、他人に漏れることはない。

### 対応は二段にする

対応すると投稿が非表示になる。**画面から戻す手段は無い**（解除は DB を直接触る）。
一度の操作で実行できると、誤って触ったときに戻せない。

[#60](https://github.com/yama-shu/575-sns/issues/60) の削除と同じく `<details>` で畳む。
`confirm()` は使わない。JavaScript が無効な環境では確認が出ないまま実行される。

**却下は一段でよい。** 投稿は変わらず、通報が閉じるだけである。

### 投稿カードを使わない

[#60](https://github.com/yama-shu/575-sns/issues/60) の `PostCard` にはいいねと通報のボタンが付いている。
運営が通報を裁く画面に、いいねや通報は要らない。

句ごとの改行だけを踏襲した表示を、この画面のために作る。

### 処理したら一覧へ戻す

対応・却下の後は `/admin/reports` へ `redirect` する。
[#60](https://github.com/yama-shu/575-sns/issues/60) のフォロー・ブロックと同じ形である。
一覧そのものが変わるため、ボタンの周りだけを差し替えても画面が食い違う。

### 409 を握りつぶさない

[#74](https://github.com/yama-shu/575-sns/issues/74) は処理済みの通報に 409 を返す。**画面でも伝える。**
別の運営が先に処理した可能性があり、黙って成功にすると二重に判断することになる。
