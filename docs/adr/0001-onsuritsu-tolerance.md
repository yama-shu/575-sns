# ADR-0001: 字余り・字足らずの許容範囲

| 項目 | 内容 |
| --- | --- |
| 状態 | **承認** |
| 決定日 | 2026-08-06 |
| 関連 | [要件定義 Q-01](../requirements/01-requirements.md#10-未決事項) / [FR-02-01](../requirements/01-requirements.md#fr-02-投稿詠む) |

---

## 1. 背景

575 は「投稿本文が五七五でなければ投稿できない」SNS である。
一方で、5/7/5 ぴったりだけを通すのは厳しすぎる。日本語の川柳・俳句では
字余り・字足らずは日常的に発生し、それを一律に弾くと投稿体験が成立しない。

そこで **「多少の字余り・字足らずは許容する」** という方針が立っている。
本 ADR はこの「多少」を、実装可能な数値として定義する。

この決定はプロダクトの根幹に関わる。緩すぎれば「五七五でしか投稿できない SNS」という
コンセプトが崩れ、厳しすぎれば誰も投稿できない。

---

## 2. 決定を左右する要因

| # | 評価軸 | 説明 |
| --- | --- | --- |
| A | **コンセプトの保持** | 「五七五になっていない文」が通ってはならない。これが崩れたらプロダクトの存在意義がない |
| B | **人間の感覚との一致** | 「これは五七五として自然」と人が感じるものが通り、「これは違う」と感じるものが弾かれること |
| C | **ルールの説明可能性** | ユーザーに一言で説明できること。判定が不透明だと不信感につながる |
| D | **実装・テストの容易さ** | 判定ロジックが検証可能であること |

優先度は **A > B > C > D**。

---

## 3. 選択肢

### 案1: 合計モーラ数のみで判定する

区切りを考えず、本文全体のモーラ数が 15〜19（17±2）に収まれば可とする。

```
「今日は本当に疲れた一日だったな」→ 17モーラ → 可
```

### 案2: 各句に許容幅を設ける

上五 4〜6 / 中七 6〜8 / 下五 4〜6 の範囲に区切れれば可とする。
合計に対する制約は設けない。

```
6 / 8 / 6 = 20モーラ → 可
4 / 6 / 4 = 14モーラ → 可
```

### 案3: 各句の許容幅 + ズレる句の数を制限する

上五 4〜6 / 中七 6〜8 / 下五 4〜6 に加えて、
**規定値（5/7/5）から外れている句は最大1句まで**とする。

```
5 / 7 / 5 = ズレ0 → 定型
6 / 7 / 5 = ズレ1 → 許容
6 / 8 / 5 = ズレ2 → 破調
```

### 案4: 字余りのみ許容し、字足らずは認めない

上五 5〜6 / 中七 7〜8 / 下五 5〜6。字足らずは破調とする。

---

## 4. 比較

| | 案1: 合計のみ | 案2: 各句の幅 | 案3: 幅 + ズレ数 | 案4: 字余りのみ |
| --- | --- | --- | --- | --- |
| **A. コンセプト保持** | ❌ 致命的 | 🔺 やや甘い | ✅ 良好 | ✅ 良好 |
| **B. 感覚との一致** | ❌ 一致しない | 🔺 極端な例が通る | ✅ 良好 | 🔺 字足らずを弾く |
| **C. 説明可能性** | ✅ 最も単純 | ✅ 単純 | 🔺 条件が2つ | ✅ 単純 |
| **D. 実装容易性** | ✅ 区切り探索が不要 | ✅ 容易 | ✅ 容易 | ✅ 容易 |
| **許容される合計** | 15〜19 | 14〜20 | 16〜18 | 17〜20 |

### 各案の詳細な評価

**案1 は却下する。**
区切りを見ないため、「今日は本当に疲れた一日だったな」のような
五七五でない17モーラの文が通ってしまう。
これは「五七五でしか投稿できない SNS」というコンセプトそのものを破壊する。
判定エンジンが不要になるので実装は最も軽いが、軽くなった結果プロダクトが消える。

**案2 は甘すぎる。**
`6/8/6 = 20モーラ` と `4/6/4 = 14モーラ` が両方通る。
20モーラの句は五七五として明らかに冗長で、14モーラは明らかに舌足らずである。
「各句が1モーラずつズレる」ことを許すと、全体としては五七五から大きく外れる。

**案4 はユーザーの要望に反する。**
「多少の字余り、字足らずでもいい」という前提に対して、字足らずを一律に禁じている。
伝統的な俳句では字余りの方が許容されやすいという背景はあるが、
575 は俳句 SNS ではないため、その規範に従う理由がない。

**案3 が最もバランスが良い。**
「1箇所だけ少しズレている」を許容し、「全体的にぐだぐだ」を弾く。
これは人間が五七五を聞いたときの感覚に最も近い。

### 案3 についての補足: 合計モーラ数の制約は不要である

案3 では「合計 16〜18」という制約を別途置きたくなるが、**これは不要**である。

ズレる句が最大1つに制限されている以上、他の2句は規定値ちょうどになる。
したがってズレる句が ±1 モーラである以上、合計は必然的に 17±1 = **16〜18** に収まる。
合計の制約は「各句の幅」と「ズレ数の制限」から自動的に導かれるため、
明示的に書くと**冗長なだけでなく、条件の重複によってバグを生む**。

この観察により、案3 のルールは以下の2条件のみで表現できる。

> 1. 上五が 4〜6、中七が 6〜8、下五が 4〜6 モーラであること
> 2. 規定値（5 / 7 / 5）から外れている句が、多くとも1句であること

条件が2つで済むため、案2 との説明コストの差はほとんどなくなる。

---

## 5. 決定

**案3 を採用する。**

### 判定ルール

本文を上五・中七・下五に区切ったとき、以下を満たすかで判定する。

| 判定 | 条件 |
| --- | --- |
| **定型** | 上五 = 5、中七 = 7、下五 = 5 |
| **許容** | 各句が「上五 4〜6 / 中七 6〜8 / 下五 4〜6」に収まり、かつ規定値から外れている句がちょうど1句 |
| **破調** | 上記のいずれにも当てはまらない |

### 判定結果の一覧（全パターン）

各句が取り得る値の組み合わせをすべて列挙する。

| 上五 | 中七 | 下五 | 合計 | ズレ数 | 判定 |
| :---: | :---: | :---: | :---: | :---: | --- |
| 5 | 7 | 5 | 17 | 0 | **定型** |
| 4 | 7 | 5 | 16 | 1 | 許容（上五が字足らず） |
| 6 | 7 | 5 | 18 | 1 | 許容（上五が字余り） |
| 5 | 6 | 5 | 16 | 1 | 許容（中七が字足らず） |
| 5 | 8 | 5 | 18 | 1 | 許容（中七が字余り） |
| 5 | 7 | 4 | 16 | 1 | 許容（下五が字足らず） |
| 5 | 7 | 6 | 18 | 1 | 許容（下五が字余り） |
| 上記以外 | | | | 2以上 | **破調** |

投稿可能なパターンは **定型1通り + 許容6通りの計7通り**に限られる。
この網羅性が、テスト設計での境界値の洗い出しをそのまま可能にする。

### ユーザーへの説明文（UI 上の表記案）

> 五七五で詠んでください。
> どこか1箇所だけなら、1音の字余り・字足らずも大丈夫です。

---

## 6. 結果

### この決定によって可能になること

- 判定ロジックが2条件の単純な述語になり、単体テストで全パターンを網羅できる
- 「投稿できるのは7パターンのみ」と明示できるため、ユーザーへの説明が具体的になる
- 「定型」と「許容」を区別できるため、定型で詠めたことに対する報酬（バッジ表示）を設計できる

### この決定によって諦めること

- **2箇所以上ズレた句は、たとえ人間が読んで自然でも投稿できない。**
  例えば `6/8/5`（合計19モーラ）は、実際の川柳では珍しくないが破調として弾かれる。
  これは案3 が「厳しめ」に倒した結果であり、意図的なトレードオフである。
- 緩和が必要になった場合は、本 ADR を「置換」とし、新しい ADR を起こして対応する。
  リリース後の実データ（破調で弾かれた文の分布）を見てから判断するのが望ましい。

### 残る論点（本 ADR では決めない）

| 論点 | 扱い |
| --- | --- |
| モーラの具体的な数え方（拗音・促音・撥音・長音・数字・アルファベット） | 詳細設計で定義する |
| 区切り位置をどう探索するか（形態素境界の扱い、複数候補があるときの選び方） | 詳細設計で定義する |
| 読みの推定を誤った場合の救済手段 | [FR-02-09](../requirements/01-requirements.md#fr-02-投稿詠む)（第2版以降） |
